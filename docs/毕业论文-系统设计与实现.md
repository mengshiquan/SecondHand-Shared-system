# 校园二手物品共享平台 — 系统设计与实现

> 本文档为毕业论文写作提供完整的系统描述，涵盖选题背景、需求分析、架构设计、数据库设计、详细实现与测试方案。

---

## 一、选题背景与意义

### 1.1 选题背景

随着高校招生规模持续扩大，校园内学生群体的闲置物品交易需求日益增长。每年毕业季，大量教材、电子产品、生活用品被低价处理或丢弃，造成资源浪费。与此同时，在校学生对高性价比二手商品存在刚性需求。

传统的校园二手交易主要依托 QQ 群、微信朋友圈、贴吧等社交平台，存在以下突出问题：

1. **信息碎片化**：商品信息分散在不同的群聊和动态中，难以检索和筛选
2. **信任机制缺失**：买卖双方身份不透明，交易纠纷频发
3. **交易流程不规范**：缺乏统一的订单管理和状态追踪机制
4. **缺乏评价体系**：买方无法参考历史交易记录判断卖家信誉

### 1.2 研究意义

本项目构建一个**面向高校校园的专属二手物品共享平台**，具有以下价值：

- **经济价值**：促进闲置物品循环利用，降低学生生活成本
- **社会价值**：践行绿色校园理念，减少物品浪费，培养可持续消费习惯
- **技术价值**：实践前后端分离架构、JWT 无状态认证、RESTful API 设计等现代软件工程方法

## 二、系统需求分析

### 2.1 用户角色

| 角色 | 权限描述 |
|------|---------|
| **未登录用户（游客）** | 浏览商品列表、查看商品详情、搜索商品、查看分类 |
| **普通用户（USER）** | 游客权限 + 发布/编辑/下架商品、创建订单、收藏商品、发表评论、管理个人资料 |
| **管理员（ADMIN）** | 普通用户权限 + 数据概览仪表板、管理所有用户/商品/订单、管理商品分类 |

### 3.3 后端分层架构

```
Controller（控制层）
  │ 接收 HTTP 请求，参数校验(@Validated)，调用 Service
  │ 返回 Result<T> 统一格式
  ↓
Service（业务逻辑层）
  │ 接口定义（service/）→ 实现类（service/impl/）
  │ 处理业务规则、权限校验、数据转换
  ↓
Mapper（数据访问层）
  │ 接口 extends BaseMapper<T>（MyBatis-Plus 内置 CRUD）
  │ 复杂查询写入 XML 映射文件（resources/mapper/*.xml）
  ↓
Entity（实体层）
  │ 数据库表映射（@TableName），软删除支持（@TableLogic）
  ↓
MySQL 数据库
```

### 3.4 前端分层架构

```
Views（页面组件）
  │ 路由级别的页面，如 Home.vue、ProductDetail.vue
  ↓
Components（通用组件）
  │ 可复用的 UI 单元，如 ProductCard.vue、AppHeader.vue
  ↓
API Modules（接口模块）
  │ 封装后端 API 调用，如 api/product.js、api/order.js
  ↓
Utils（工具层）
  │ request.js（Axios 实例 + 拦截器）、auth.js（Token 管理）
  ↓
Stores（状态管理）
  │ Pinia Store，管理用户信息等全局状态
```

## 五、系统核心实现

### 5.1 用户认证与授权

系统采用 **JWT（JSON Web Token）** 实现无状态认证，无需在服务端维护 Session。

**认证流程：**

```
1. 用户提交用户名 + 密码 → POST /api/user/login
2. 服务端验证密码（MD5 比对），生成 JWT Token
3. Token 包含载荷：userId（用户ID）、role（角色）、exp（过期时间 24h）
4. 前端将 Token 存入 localStorage（key: secondhand_token）
5. 后续请求通过 Axios 请求拦截器自动附加 Authorization: Bearer <token>
6. JwtInterceptor 拦截请求，验证 Token 有效性
7. 验证通过后将 userId 和 role 存入 Request Attribute
8. 业务层通过 UserContext.getUserId() 获取当前用户
```

**前端路由守卫：**
- `meta.requiresAuth`：需要登录的页面，未登录重定向到 `/login`
- `meta.requiresAdmin`：需要管理员角色，非管理员重定向到首页
- `meta.guest`：仅游客可访问（登录/注册页），已登录用户重定向到首页

### 5.2 商品模块实现

**核心类设计：**

| 类 | 包路径 | 职责 |
|----|--------|------|
| ProductController | `controller/` | REST 接口，处理发布/编辑/删除/下架/列表/详情请求 |
| ProductServiceImpl | `service/impl/` | 业务逻辑：权限校验（checkOwner）、状态管理、浏览量累加 |
| ProductMapper | `mapper/` | 数据访问，自定义查询（selectProductPage、selectProductDetail） |
| Product.java | `entity/` | 实体映射，@TableLogic 软删除 |
| ProductDTO.java | `dto/` | 前端输入数据对象 |
| ProductVO.java | `vo/` | 输出视图对象（含 sellerName、categoryName 等联表字段） |
| ProductQueryDTO.java | `dto/` | 分页查询条件（pageNum / pageSize / keyword / categoryId / status / sortBy） |

**关键业务逻辑：**
- 发布商品时自动设置 `userId`（当前用户）、`status`（ON_SALE）、`viewCount`（0），图片列表通过 Hutool JSON 序列化存储
- 编辑商品前校验所有权（`checkOwner`：比较 `product.userId` 与当前用户ID）
- 删除商品：普通用户仅能删除自己的商品，管理员可删除任意商品
- 商品列表支持多维度筛选：关键词搜索、分类筛选（含子分类）、状态过滤、排序方式（最新/价格）
- 商品详情自动累加浏览量（每次访问 `viewCount + 1`）

### 5.3 订单模块实现

**状态流转机制：**

| 当前状态 | 操作 | 操作人 | 目标状态 | 副作用 |
|---------|------|--------|---------|--------|
| PENDING | 确认付款 | 买家 | PAID | — |
| PENDING | 取消订单 | 买家 | CANCELLED | 商品状态恢复为 ON_SALE |
| PAID | 确认发货 | 卖家 | SHIPPED | — |
| SHIPPED | 确认收货 | 买家 | COMPLETED | — |

- 创建订单时生成全局唯一的订单编号（雪花ID算法）
- 每次状态变更前校验操作权限（买家/卖家身份）
- 取消订单时将关联商品状态从 SOLD 恢复为 ON_SALE，实现商品自动重新上架
- 前端为待付款订单展示倒计时组件（截至 `expireTime`），过期提示"已超时"

### 5.4 文件上传模块

- 前端使用 Element Plus `el-upload` 组件，自定义 `http-request`（通过 Axios 以 FormData 上传）
- 后端 `FileController` 接收 MultipartFile，使用 UUID + 原扩展名生成唯一文件名
- 上传路径配置在 `application.yml`（`file.upload-path: ./uploads/`）
- 通过 `WebMvcConfig` 将 `/api/uploads/**` 映射到文件系统实际路径，实现 URL 直接访问
- 图片限制：单文件最大 10MB，每次请求最大 20MB

### 5.5 后台管理模块

- 数据概览页使用 **ECharts** 渲染：分类分布饼图 + 订单状态柱状图
- 表格支持分页展示，操作列提供格式化后的中文状态标签（带颜色区分）
- 图表渲染采用 `nextTick` + `offsetParent` 检测确保 DOM 就绪后初始化

## 六、统一返回格式与异常处理

### 6.1 Result\<T\> 通用响应封装

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

| code | 含义 | 前端处理 |
|------|------|---------|
| 200 | 成功 | 正常展示数据 |
| 401 | 未认证 | 清除 Token，跳转登录页 |
| 500 | 业务异常 | ElMessage.error 提示 |

### 6.2 全局异常处理

- `BusinessException`：业务异常，code=500，message 为具体错误描述
- `GlobalExceptionHandler`：@ControllerAdvice 全局捕获异常，统一转换为 Result 格式
- 前端响应拦截器：code≠200 时自动弹窗提示，code=401 时清除登录态

## 八、总结与展望

### 8.1 项目主要工作

1. 完成了校园二手物品共享平台的需求分析，梳理了六大功能模块与订单状态流转逻辑
2. 设计了前后端分离的系统架构，后端采用 Spring Boot + MyBatis-Plus 三层架构，前端采用 Vue 3 + Element Plus 组件化开发
3. 实现了完整的用户认证体系（JWT Token + 路由守卫 + 请求拦截器）、商品发布与管理、订单状态流转、收藏与评论系统
4. 建立了统一的数据返回格式与全局异常处理机制
5. 设计了品牌化的视觉规范（Design Token），实现了骨架屏加载态、交错入场动画、响应式布局等前端体验优化
6. 编写了数据库建表脚本与初始化数据（7 个一级分类 + 40+ 个二级子分类）
