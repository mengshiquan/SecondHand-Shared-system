## 二、表间关联关系

| 关系 | 基数 | 关联字段 | 说明 |
|---|---|---|---|
| t_user → t_product | 1:N | `t_product.user_id` | 一个用户可发布多个商品 |
| t_category → t_category | 1:N（自引用） | `t_category.parent_id` | 一级分类下多个二级分类 |
| t_category → t_product | 1:N | `t_product.category_id` | 一个分类下多个商品 |
| t_user → t_order（买家） | 1:N | `t_order.buyer_id` | 一个买家可有多笔订单 |
| t_user → t_order（卖家） | 1:N | `t_order.seller_id` | 一个卖家可有多笔订单 |
| t_product → t_order | 1:N | `t_order.product_id` | 一个商品可有多笔历史订单（同一时刻最多一笔有效） |
| t_address → t_order | 1:N | `t_order.address_id` | 一个地址可被多笔订单引用（下单时快照地址文本） |
| t_user → t_address | 1:N | `t_address.user_id` | 一个用户可有多个收货地址（最多 10） |
| t_user ↔ t_product（收藏） | M:N | 中间表 `t_favorite` | 唯一约束 `(user_id, product_id)` |
| t_user ↔ t_product（购物车） | M:N | 中间表 `t_cart` | 唯一约束 `(user_id, product_id)` |
| t_user ↔ t_product（评论） | M:N（带属性） | 中间表 `t_comment` | 附带 content、rating，是关联实体 |
| t_user → t_notification | 1:N | `t_notification.user_id` | 一个用户有多条通知 |
| t_user ↔ t_user（聊天） | M:N（带属性） | 中间表 `t_chat_message` | `sender_id` / `receiver_id` 双外键 |
| t_user ↔ t_user（投诉） | M:N（带属性） | 中间表 `t_complaint` | `reporter_id` / `target_user_id` / `handler_id` 三角色 |
| t_user → t_appeal（申诉人） | 1:N | `t_appeal.user_id` | 一个用户可多次申诉 |
| t_user → t_appeal（处理人） | 1:N | `t_appeal.handler_id` | 管理员处理多笔申诉 |

按基数汇总：

- **一对多**：user→product、category→product、category→category、user→order(buyer)、user→order(seller)、product→order、address→order、user→address、user→notification、user→appeal(申诉人)、user→appeal(处理人)、user→complaint(处理人)
- **多对多**：user↔product（favorite、cart、comment 三条通道）、user↔user（chat_message、complaint 两条通道）
- **一对一**：无独立一对一表；`t_order` 与 `t_product` 在同一时刻业务上近似一对一（CAS 防超卖），但历史维度是多对一

**顶层（Context）数据流**

```
用户  → [系统] → MySQL(12张表) + Redis
支付宝 → [支付回调] → D4订单
管理员 → [后台] → D1/D2/D3/D4/D9/D10
```

**0 层图：主要加工（Process）与数据流**

| 编号 | 加工名称 | 输入数据流（来源） | 输出数据流（去向） |
|---|---|---|---|
| P1 | 用户管理 | 注册/登录请求（用户）→ 验证码校验 | D1 写入；通知 D11 |
| P2 | 商品管理 | 发布/编辑/上下架（卖家） | D3 写入；D11 通知卖家 |
| P3 | 商品浏览/检索 | 搜索/分类/排序请求（游客/用户） | D3、D2 读取；浏览量→Redis→定时回写 D3 |
| P4 | 咨询卖家 | 咨询内容（买家） | 频控→Redis；通知→D11 |
| P5 | 购物车管理 | 加购/移除/结算（买家） | D8、D5 读写 |
| P6 | 订单管理 | 下单/取消/发货/收货/退款/仲裁 | D4 写入；D3 状态更新；D11 通知；Redis 分布式锁 |
| P7 | 支付处理 | 预下单请求（买家）→ 支付宝/微信 → 回调 | D4 更新（pay_channel / pay_trade_no / payment_time）；D3 更新为 SOLD；D11 通知 |
| P8 | 收藏管理 | 收藏/取消/列表（用户） | D5 读写 |
| P9 | 评论管理 | 发表/删除评论（用户） | D6 写入 |
| P10 | 地址管理 | 地址 CRUD（用户） | D7 写入 |
| P11 | 通知管理 | 通知列表/已读（用户） | D11 读写 |
| P12 | 聊天 | 发送/编辑/删除消息（用户）+ WebSocket 推送 | D12 写入 |
| P13 | 投诉/申诉 | 提交投诉/申诉（用户） | D9/D10 写入 |
| P14 | 后台治理 | 审核/投诉处理/申诉处理/拉黑（管理员） | D1 黑名单字段、D9/D10 状态、D11 通知 |
| P15 | 统计导出 | 统计/导出请求（管理员） | D4 聚合（selectSalesRows）；Excel 文件 |

**关键数据流细节**

- 「下单」：`用户 → P6 → [Redis锁+CAS] → D4(新订单) + D3(ON_SALE→OFF_SHELF)`
- 「支付成功」：`支付宝/微信 → P7 → D4(PENDING→PAID, 记录渠道/交易号) → D3(SOLD) → D11(通知卖家)`
- 「取消/退款」：`P6 → D4(CANCELLED) → D3(恢复ON_SALE)`
- 「超时处理」：`定时器 → P6 → D4(PENDING超时→CANCELLED) → D3(恢复)`
- 「小黑屋扫描」：`定时器 → P14 → D1(黑名单字段) + D11(通知)`

## 四、关键状态机（补充绘图参考）

### 订单状态

```
PENDING(待付款) → PAID(已付款) → SHIPPED(已发货) → COMPLETED(已完成)
       ↘ CANCELLED(已取消)
```

### 退款状态

```
NONE → REQUESTED → SELLER_AGREED / SELLER_REJECTED → ARBITRATION → ARBITRATION_REFUND / ARBITRATION_MAINTAIN
```

### 商品状态

```
ON_SALE(在售) → SOLD(已售) / OFF_SHELF(下架)
取消/退款后可恢复 ON_SALE
```
