# 项目业务与模块分析

> 依据 README、`pom.xml`、启动类以及后端 Controller / Service / Mapper 三层代码整理。

## 一、项目整体业务

这是一个**前后端分离的「校园二手物品共享 / 交易平台」**，面向校园场景：

- 学生注册登录后可发布、浏览、搜索、收藏二手商品。
- 通过购物车下单支付（支付宝沙箱扫码 + 微信模拟收银台）。
- 卖家发货、买家确认收货，支持退款 / 售后 / 平台仲裁。
- 管理后台负责审核、治理、统计与数据导出。

**技术栈**

| 层 | 技术 |
|---|---|
| 后端 | Spring Boot 3.3.5 · Java 17 · MyBatis-Plus 3.5.9 · MySQL 8 · Redis · JWT（JJWT 0.12.6） |
| 前端 | Vue 3 · Vite · Element Plus · Pinia · ECharts · Axios |
| 中间能力 | BCrypt 密码哈希 · Redis 缓存/分布式锁/频控/令牌黑名单 · EasyExcel 导出 · WebSocket 实时聊天 · 支付宝 SDK |

## 四、各模块详细分析

### 1. 用户与认证模块

- **代码**：`UserController`、`CaptchaController`、`UserServiceImpl`、`UserMapper`
- **业务**：账号体系（登录/注册/资料/密码/注销）+ 图形验证码人机校验。
- **核心接口**
  - `GET /captcha`：生成 4 位验证码，`key + base64 图片`，答案存 Redis 5 分钟。
  - `POST /user/login`：登录，返回 `LoginVO`（token + 用户信息）。
  - `POST /user/register`：注册。
  - `GET /user/info`、`PUT /user/profile`、`PUT /user/password`、`GET /user/blacklist-status`、`PUT /user/deactivate`。
- **业务逻辑**
  - 验证码「一次性消费」，读取即删除，防重放。
  - 密码兼容 BCrypt 新格式与 MD5 旧格式，旧密码匹配成功后自动升级为 BCrypt。
  - 注册校验用户名/学号唯一性（含已注销的逻辑删除残留行），注册后 `verifyStatus=PENDING`，需管理员审核。
  - 登录校验账号状态：`0=禁用`、`2=已注销` 均拒绝。
  - 注销需校验密码、且不能有未完成订单；管理员账号不允许注销。
  - `UserMapper` 用 `@Select` 绕过逻辑删除统计用户名/学号占用。

### 2. 商品模块

- **代码**：`ProductController`、`ProductServiceImpl`、`ProductMapper`
- **业务**：二手商品发布、检索、详情浏览、上下架、咨询卖家。
- **核心接口**
  - `POST /product`（发布）、`PUT /product`（编辑）、`DELETE /product/{id}`、`PUT /product/{id}/off-shelf`。
  - `GET /product/list`（分页/搜索/分类/排序）、`GET /product/my`、`GET /product/detail/{id}`、`POST /product/{id}/contact`。
- **业务逻辑**
  - 发布/编辑需通过 `VerifyGuard.requireVerified`（校园认证通过才可）。
  - 图片以 JSON 数组存库；公开列表默认只展示 `ON_SALE`。
  - 详情走 Redis 缓存，`favorited` 用户维度字段不进缓存（防止跨用户泄漏），命中后单独重算。
  - 浏览量：`SETNX` 去重（同一用户同一商品 24h 只计一次）+ Lua 原子自增，每 5 分钟 `syncViewCountToDb` 用 `SCAN` 回写 MySQL。
  - `contactSeller`：校验商品在售、不能咨询自己，Redis 频控（同一买家对同一卖家每天 ≤10 条），以通知形式送达卖家。

### 3. 分类模块

- **代码**：`CategoryController`、`CategoryServiceImpl`、`CategoryMapper`
- **业务**：两级商品分类树的读取与缓存。
- **核心接口**
  - `GET /category/list`（扁平）、`GET /category/main`（一级）、`GET /category/sub/{parentId}`（子级）、`GET /category/tree`（嵌套树）。
- **业务逻辑**
  - 分类树缓存进 Redis；`save/updateById/removeById` 覆写后统一失效缓存。
  - 两级限制在后台维护时强制校验（不能挂三级、已有子分类的不能降级为子分类）。

### 4. 购物车模块

- **代码**：`CartController`、`CartServiceImpl`、`CartMapper`
- **业务**：加购、分组列表、移入收藏、批量结算下单。
- **核心接口**
  - `GET /cart/list`、`POST /cart/{productId}`、`DELETE /cart/{id}`、`DELETE /cart/batch`、`POST /cart/move-to-favorite`、`DELETE /cart/clear`、`POST /cart/checkout`。
- **业务逻辑**
  - 加购需认证通过，校验商品 `ON_SALE` 且不能买自己的商品、不能重复加购。
  - `CartMapper.physicalDelete` 物理删除，避免唯一索引 `(user_id, product_id)` 被逻辑删除残留行占用。
  - `listMine` 批量装配商品/卖家/分类，标记失效商品（`invalid=true`）。
  - `checkout` 循环调用 `OrderService.createOrder` 逐商品下单，成功后移出购物车。

### 5. 收货地址模块

- **代码**：`AddressController`、`AddressServiceImpl`、`AddressMapper`
- **业务**：买家收货地址 CRUD 与默认地址管理。
- **核心接口**：`GET /address/list`、`POST /address`、`PUT /address/{id}`、`DELETE /address/{id}`、`PUT /address/{id}/default`。
- **业务逻辑**：每人最多 10 条；第一个地址自动设为默认；设默认时先清空其他默认；删除默认地址后自动把最近一条设为默认。

### 6. 订单模块

- **代码**：`OrderController`、`OrderServiceImpl`、`OrderMapper`
- **业务**：下单、支付后发货收货、取消、退款/仲裁，是交易核心。
- **核心接口**
  - `POST /order`、`GET /order/list`、`GET /order/status-counts`、`GET /order/{id}`。
  - `PUT /order/{id}/status`（发货/收货/取消）、`POST /order/{id}/cancel`、`PUT /order/{id}/address`。
  - `POST /order/{id}/refund`、`PUT /order/{id}/refund/handle`、`POST /order/{id}/arbitration`、`DELETE /order/{id}`。
- **业务逻辑**
  - 状态机：`PENDING → PAID → SHIPPED → COMPLETED`，`PENDING → CANCELLED`。
  - 创建订单：对同一商品加 Redis 分布式锁，锁覆盖「校验→下单→下架→事务提交」全程；商品下架用 CAS 条件更新（仅 `ON_SALE` 才改 `OFF_SHELF`）做防超卖纵深防御；下单后通知卖家。
  - 30 分钟预留超时，`validatePayable` 对过期单自动取消并恢复商品。
  - `markPaid`：CAS 仅 `PENDING→PAID`，回调与轮询并发时幂等；超时单用 `REQUIRES_NEW` 独立事务取消，避免主事务回滚导致订单僵死；支付成功商品标记 `SOLD` 并通知卖家。
  - `updateStatus`：先校验权限（买家付款/收货、卖家发货），退款进行中（`REQUESTED/ARBITRATION`）禁止发货/收货流转。
  - 退款状态机：`NONE → REQUESTED → SELLER_AGREED/SELLER_REJECTED → ARBITRATION → ARBITRATION_REFUND/ARBITRATION_MAINTAIN`；卖家拒绝后买家 72 小时内可申请仲裁。
  - 定时任务：每 5 分钟取消过期待付款单；每 10 分钟自动同意超过 48h 未处理的退款；取消/退款后恢复商品 `ON_SALE`。
  - `statusCounts` 按「买家待付款/待收货、卖家待发货/待处理退款」拆解角标。

### 7. 支付模块

- **代码**：`PayController`（调用 `OrderService`、`AliPayConfig`）
- **业务**：支付宝沙箱扫码付 + 微信模拟收银台 + 支付状态轮询。
- **核心接口**
  - `POST /pay/alipay/create/{orderId}`、`POST /pay/alipay/notify`（免登录）。
  - `POST /pay/wechat/create/{orderId}`、`POST /pay/wechat/notify/{orderNo}`。
  - `GET /pay/status/{orderId}`。
- **业务逻辑**
  - 支付宝 `precreate` 生成沙箱二维码；异步回调 `rsaCheckV1` RSA2 验签，仅 `TRADE_SUCCESS/TRADE_FINISHED` 落单。
  - 本地无公网时，`GET /pay/status` 轮询主动调 `alipay.trade.query` 补单。
  - 微信为模拟收银台：生成 `weixin://...mock=` 二维码，模拟扫码回调仅买家可触发。
  - 最终都走 `OrderService.markPaid` 的 CAS 幂等落单。

### 8. 收藏模块

- **代码**：`FavoriteController`、`FavoriteServiceImpl`、`FavoriteMapper`
- **核心接口**：`POST /favorite/{productId}`（收藏/取消）、`GET /favorite/{productId}`（是否已收藏）、`GET /favorite/list`、`DELETE /favorite/batch`。
- **业务逻辑**：需认证通过；收藏/取消用分布式锁防并发双击；取消收藏物理删除，规避唯一索引残留。

### 9. 评论模块

- **代码**：`CommentController`、`CommentServiceImpl`、`CommentMapper`
- **核心接口**：`POST /comment`、`DELETE /comment/{id}`、`GET /comment/list/{productId}`。
- **业务逻辑**：发表需认证通过，带评分 `rating`（1–5）；删除仅评论本人或管理员；列表通过 `selectCommentPage` 联表返回用户信息。

### 10. 通知模块

- **代码**：`NotificationController`、`NotificationServiceImpl`、`NotificationMapper`
- **核心接口**：`GET /notification/list`、`GET /notification/unread-count`、`PUT /notification/{id}/read`、`PUT /notification/read-all`、`DELETE /notification/{id}`、`DELETE /notification/clear`。
- **业务逻辑**：`send(userId,title,content,type)` 被订单/支付/认证/投诉/仲裁/咨询等模块复用；每天 4 点清理 30 天前的通知。

### 11. 聊天模块

- **代码**：`ChatController`、`ChatServiceImpl`、`ChatMessageMapper`、`ChatWebSocketHandler`
- **业务**：买卖家围绕商品的实时沟通。
- **核心接口**
  - `GET /chat/conversations`、`GET /chat/messages/{peerId}`（游标分页）、`POST /chat/send`、`POST /chat/read/{peerId}`、`GET /chat/unread`。
  - `PUT /chat/message/{id}`（编辑）、`DELETE /chat/message/{id}`、`DELETE /chat/conversation/{peerId}`。
- **业务逻辑**：REST 负责落库与查询，`/ws/chat` WebSocket 负责实时推送；发送/编辑/删除后向对方推送对应事件；拉取消息自动把对方消息标记已读；消息关联商品标题。

### 12. 投诉与申诉模块

- **代码**：`ComplaintController`、`AppealController`、`AdminService`（处理部分）
- **核心接口**：`POST /complaint`、`POST /appeal`；后台 `GET/PUT /admin/complaints/...`、`GET/PUT /admin/appeals/...`。
- **业务逻辑**
  - 投诉：目标用户必须存在、不能投诉自己、不能投诉管理员、同一目标只允许一条 `PENDING`。
  - 申诉：同一用户只允许一条 `PENDING`。
  - 后台处理投诉通过 → 对被投诉人拉黑；处理申诉通过 → 解除小黑屋。

### 13. 小黑屋模块

- **代码**：`BlacklistServiceImpl`、`BlacklistService`、后台 `AdminController` 相关端点
- **核心接口**：`POST /admin/blacklist/scan`、`GET /admin/blacklist`、`PUT /admin/users/{id}/blacklist`、`PUT /admin/users/{id}/unblacklist`。
- **业务逻辑**
  - 每天 3 点自动扫描（也可手动触发）：卖家「90 天内收到 1 星 ≥5 且占比 >30%」拉黑；买家「发出 1 星 >80% 且无购买记录」拉黑。
  - 惩罚天数递进：`基础 14 天 × 2^(历史违规次数)`；解除后 `blacklistCount+1`，只统计解封后的新评论。
  - 拉黑/解封均发站内通知。

### 14. 后台管理模块

- **代码**：`AdminController`、`AdminExportController`、`AdminStatsController`、`AdminServiceImpl`、`SalesStatsServiceImpl`
- **业务**：管理员/超管的后台运营、审核、治理、统计与导出。
- **核心接口**
  - `GET /admin/dashboard`、`GET /admin/category-stats`、`GET /admin/notifications`。
  - 用户：`GET /admin/users`、`PUT /admin/users/verify`、`PUT /admin/users/{id}/status|role|reset-password`、`POST /admin/users`、`PUT/DELETE /admin/users/{id}`。
  - 商品/订单：`GET /admin/products`、`GET /admin/orders`、`PUT/DELETE /admin/products/{id}`、`PUT/DELETE /admin/orders/{id}`、`PUT /admin/order/{id}/arbitration`。
  - 分类：`POST/DELETE /admin/category`。
  - 投诉/申诉/黑名单处理端点。
  - 管理员管理（仅超管）：`GET/POST/PUT/DELETE /admin/admins`。
  - 统计与导出：`GET /admin/stats/sales`、`GET /admin/stats/sales/export`、`GET /admin/export/users|products|orders`。
- **业务逻辑**
  - `checkAdmin` / `checkSuperAdmin` 双重权限校验；超管才能增删改管理员、调整角色。
  - 仪表盘数据 Redis 缓存；销售统计基于 `COMPLETED` 订单（以 `update_time` 为成交时间），按日/周/月或自定义区间，输出金额、分类、卖家维度。
  - 导出用 EasyExcel（用户/商品/订单/销售明细）。
  - 认证审核批量通过/拒绝并通知；删除用户做级联清理（商品下架、未完成订单取消、收藏/地址/购物车清除，并失效商品详情缓存）。

### 15. 文件模块

- **代码**：`FileController`、`FileServerController`、`FileUploadUtil`
- **核心接口**：`POST /file/upload`（图片上传）、`GET /uploads/{filename}`（文件访问）。
- **业务逻辑**：启动时把上传目录解析为绝对路径；访问时做 `getCanonicalPath` 防路径穿越。

## 六、关键状态机

### 订单状态

```
PENDING(待付款) → PAID(已付款) → SHIPPED(已发货) → COMPLETED(已完成)
       ↘ CANCELLED(已取消)
```

### 退款状态

```
NONE → REQUESTED → SELLER_AGREED / SELLER_REJECTED → ARBITRATION → ARBITRATION_REFUND / ARBITRATION_MAINTAIN
```

### 商品状态

```
ON_SALE(在售) → SOLD(已售) / OFF_SHELF(下架)
取消/退款后可恢复 ON_SALE
```
